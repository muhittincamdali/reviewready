How to fix

[A]      Add the key in the target's Info tab
         1. In Xcode, select the target, open Info, and add the key with a sentence that says what
            the app does with the data. Xcode stores it as the INFOPLIST_KEY_<key> build setting.
         2. If the app never uses this feature, remove the code or the package that uses it instead.
         https://github.com/muhittincamdali/reviewready/blob/main/docs/guides/purpose-strings.md

[B]      Write a one-sentence string
         1. Set the INFOPLIST_KEY_<key> build setting (target > Info in Xcode) to one complete
            sentence that says what the app does with the data.
         https://github.com/muhittincamdali/reviewready/blob/main/docs/guides/purpose-strings.md

[C]      Export the icon without transparency
         1. Export the 1024 × 1024 icon as an opaque PNG: give it a solid background and turn off
            "Transparency" or "Alpha" in the export settings (in Preview: File > Export, untick
            Alpha).
         2. Check it with: sips -g hasAlpha path/to/icon.png (it should print hasAlpha: no).
         https://github.com/muhittincamdali/reviewready/blob/main/docs/guides/app-icon.md

[D]      Build with Xcode 26 or later
         1. Change the pinned version to Xcode 26 or later (for example 27.1) in the file and line
            the finding names, and use a runner or build image that has it.
         2. Fix the build warnings and errors the newer SDK reports before the next upload.
         https://github.com/muhittincamdali/reviewready/blob/main/docs/guides/xcode-and-ios-minimums.md

[E]      Raise the deployment target
         1. Set IPHONEOS_DEPLOYMENT_TARGET of the app target to 13.0 or later (target > General >
            Minimum Deployments in Xcode), and raise platform :ios in the Podfile to match.
         2. Remove the code paths that only ran on older iOS versions.
         https://github.com/muhittincamdali/reviewready/blob/main/docs/guides/xcode-and-ios-minimums.md

[F]      Say why the app needs access
         1. Replace the text with one sentence that names what the app does with the data, for
            example "Take a photo of your meal to log it" rather than "needs camera access".
         https://github.com/muhittincamdali/reviewready/blob/main/docs/guides/purpose-strings.md

[G]      Declare the app's encryption
         1. Set the INFOPLIST_KEY_ITSAppUsesNonExemptEncryption build setting to NO if the app uses
            no encryption or only exempt encryption such as HTTPS, or to YES with
            ITSEncryptionExportComplianceCode otherwise.
         https://github.com/muhittincamdali/reviewready/blob/main/docs/guides/export-compliance.md

[H]      Let people delete their account in the app
         1. Add a Delete account action that is easy to find, usually in the account settings, and
            that deletes the account record with its personal data, not only deactivates it.
         2. If deletion finishes on a website, link straight to that page. With Sign in with Apple,
            also revoke the user's tokens.
         3. If the app already has it under words reviewready does not know, turn the finding off
            with --ignore RVW301.
         https://github.com/muhittincamdali/reviewready/blob/main/docs/guides/accounts-and-sign-in.md

[I]      Offer Sign in with Apple next to the other login
         1. Add Sign in with Apple (AuthenticationServices on iOS, sign_in_with_apple on Flutter,
            expo-apple-authentication or @invertase/react-native-apple-authentication on React
            Native) and the Sign in with Apple capability.
         2. If the app falls under one of the exceptions of guideline 4.8, or offers another login
            service with the listed features, turn the finding off with --ignore RVW401.
         https://github.com/muhittincamdali/reviewready/blob/main/docs/guides/accounts-and-sign-in.md

[J]      Add the file to the app target
         1. Select PrivacyInfo.xcprivacy in Xcode, open the File inspector and tick the app target
            under Target Membership, so it appears in Build Phases > Copy Bundle Resources.
         https://github.com/muhittincamdali/reviewready/blob/main/docs/guides/privacy-manifest.md
